# Question
* Did we port over FrameStabilityContainer? — No. It lived inside osu's DrawableRuleset (dropped by
  the port plan). It does two jobs: (1) apply the gameplay clock to the playfield subtree — now done
  directly by GameplayClockContainer setting Content.Clock (see fix above); (2) frame stability
  proper — re-running updates in fixed ≤16 ms sub-steps so judgement logic sees deterministic elapsed
  times even at low/erratic frame rates (osu needs this for replay determinism). Garbus has no
  replays, so (2) was consciously skipped; if judgement precision at low FPS ever matters, the class
  is vendorable standalone (osu.Game/Rulesets/UI/FrameStabilityContainer.cs) and would wrap the
  playfield inside PlayScreen's clock container.
